### Worktree and simulator cleanup

**Audit first. Remove clean, merged, unused worktrees and regenerable caches, and report them. Ask before deleting anything else.** A disk-usage question is read-only. Untracked and ignored files may be valuable even when the branch is merged.

1. Record available disk space with the host's native tools. Resolve the repository and profile root, then run `bun "<profile>/tools/workflow/worktree-audit.ts" "<repository>" --base <local-base-ref> --json`. Read paths from `git worktree list`, not guessed directory names. The helper reads local Git state and does not fetch or establish remote PR status.
2. Treat every bucket as advice. Inspect branch/head, merge evidence, tracked changes, untracked and ignored files, and real disk usage. Unknown activity metadata means hold for investigation. Ask which native sessions or worktrees are still in use when the scoped task artifacts cannot establish that. Do not invent a pinned-chat API or scan unrelated private history.
3. List exact resolved candidate paths, their contents at risk, and evidence that each is no longer needed. Verify that every path belongs to the intended repository/worktree root. A worktree with a merged branch, no tracked changes, no untracked files, only regenerable ignored files, and evidence that nothing uses it can be removed without asking. The audit finds a session only by its starting directory, so a missing session match is not evidence that nothing uses a worktree. A dirty worktree, one holding other ignored or user data, or one whose use is unknown needs the user's approval for those exact paths. A merged branch alone is insufficient.
4. Prefer `git worktree remove <exact-path>`. Do not force a dirty worktree away. If `git worktree remove` fails, for example because a process holds a file or a path is too long on Windows, stop and report it. Never fall back to `--force` or `rm -rf` on your own. Only when the user approves discarding the listed contents, verify the resolved target again and run the exact approved operation. On Windows use native PowerShell with `-LiteralPath` for leftover files; never pass enumerated paths to another shell. Run `git worktree prune` only after the removals.
5. Clean caches on any OS, and simulators only on macOS. Package caches are regenerable and can be deleted and reported. Delete them with the owning tool's clean command, for example `go clean -modcache`, `uv cache clean`, `bun pm cache rm`, or `pnpm store prune`. Do not run `brew cleanup`, which also uninstalls old formula versions. Xcode DerivedData has no clean command; delete a project's folder under `~/Library/Developer/Xcode/DerivedData` only while Xcode is closed. Do not remove profile/session data as a cache. Browser profiles, including agent-chrome folders, are never caches. Simulator cleanup applies only on a macOS host with verified `xcrun simctl` support. Inspect the actual device/runtime inventory and active usage, then propose exact stale IDs. Deleting simulators or runtimes needs approval for the exact IDs.
6. Re-list worktrees and measure disk space afterward. Report the removals, measured space reclaimed, and each held candidate with its reason.

**Reply:** before/after disk space, exact paths removed, and evidence or uncertainty for held candidates.
