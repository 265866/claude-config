### Pause safely

**Leave a checkpoint a fresh session can resume.** Pause only on an explicit pause request or an unavoidable session boundary. "Going to bed, keep going" remains an instruction to continue.

1. Finish the current atomic step or restore its known-good state. Start nothing new. Ask active children to reach a safe boundary and return their owned files and evidence; do not abruptly kill a writer mid-update. Stop only the monitors and processes this run owns.
2. Do not create a PR, deploy, delete, post, or mutate an external service merely to pause. Pushing a checkpoint to a branch this task created is allowed. Any other remote action needs existing approval for the exact action.
3. Keep work durable on disk. Commit a clean checkpoint, marked work-in-progress in the repository's commit convention, with the **commit-agent** agent, scoped to this run's exact owned edits. When this task created a branch, push the checkpoint to it; otherwise keep it local. Do not collect unrelated user or worker changes. If the code is not commit-ready, preserve the working files and record the failing gate rather than creating a broken catch-all commit.
4. Write a resume note in the named task-artifact directory. Without such a directory, use a location that survives a reboot and that git never tracks: `$(git rev-parse --path-format=absolute --git-common-dir)/claude-pause/<branch, or the short commit hash when HEAD is detached>/`, which every worktree of the repository shares, or a new subdirectory under the active profile's directory when there is no repository. Neither location syncs to another machine. Return the resolved absolute path. Capture intent, verified progress, current branch/head, owned uncommitted files, running/stopped agents and processes, blockers, key evidence, and the first next action. For native workflows include the session ID, run ID, generated script path, arguments, and unresolved result units. Link an existing decision trail and exact-head receipts rather than duplicating them into a completion inbox. Record self-paced checks and background process monitors to restart on resume, and fixed cron tasks to inspect before creating replacements. Do not promise workers or workflow execution will survive exit; use [the execution reference](../references/execution.md) when reconstructing remaining work.

**Reply:** current phase, durable artifact paths, scoped commit or uncommitted state, verification gaps, and the first action on resume.
